# Project structure

```
/
├── .kiro/                 # specs, steering, hooks, MCP settings (committed, never gitignored)
├── ghostmap-model/        # graph model: nodes, edges, evidence, provenance, confidence (no deps)
├── ghostmap-core/
│   ├── layer/source/      # L1 tree-sitter
│   ├── layer/bytecode/    # L2 ASM
│   ├── layer/wiring/      # L3 Spring XML + annotations
│   ├── layer/runtime/     # L4 reads probe output
│   ├── join/              # join policy, rules R1..Rn, confidence algebra
│   ├── cards/             # transaction card builder
│   └── report/            # blind-spot / coverage report
├── ghostmap-probe/        # Java agent (--release 17), shaded jar
├── ghostmap-cli/          # `ghostmap index|probe|join|card|bench`
├── ghostmap-mcp/          # MCP server exposing the tools in design.md
├── web/                   # TypeScript/Vite/React UI (static)
├── fixtures/haunted-house/# synthetic Spring app with ground-truth edges (ours, written here)
├── bench/                 # AST-only baseline + benchmark scripts, published results
├── snapshots/             # generated snapshots for the demo targets (regenerated by hook)
└── docs/                  # demo script, Kiro usage write-up, architecture notes
```

## Rules
- Layers depend only on `ghostmap-model`; layers never depend on each other. Only `join/` sees all layers.
- Each layer emits `LayerFacts` (nodes + edges + evidence); the join policy is the only place edges are merged
  or scored.
- Join rules live one-per-class in `join/rules/`, named `R<nn><Name>` (e.g. `R04RuntimeFloor`), each with a
  matching `R<nn><Name>Properties` jqwik test.
- Package root: `dev.ghostmap` (placeholder until the GitHub org/name is decided).
- Demo target sources are fetched by script into `bench/targets/` (gitignored), never vendored.
